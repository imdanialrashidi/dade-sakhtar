فاکتوریل و توان با ورودی کوچک، جواب‌های کوچک می‌دهند. آکرمن برعکس است: با ورودی‌های کوچک شروع می‌کند و خیلی زود از کنترل خارج می‌شود. همین آن را به نمونهٔ معیارِ «رشدِ فراتر از معمول» تبدیل کرده است.

<Prerequisite ids={["recursion-and-factorial"]} />

## تعریف سه‌حالته

 <Formula
   id="ack-def"
   latex={"A(0,n) = n+1"}
   caption="حالت پایهٔ آکرمن"
 />

 <Formula
   id="ack-edge"
   latex={"A(m,0) = A(m-1,1)"}
   caption="حالت حاشیهٔ آکرمن"
 />

 <Formula
   id="ack-nest"
   latex={"A(m,n) = A(m-1,A(m,n-1))"}
   caption="حالت تودرتوی آکرمن"
 />

```
int A(int m, int n) {
  if (m == 0) return n + 1;
  if (n == 0) return A(m - 1, 1);
  return A(m - 1, A(m, n - 1));
}
```

ترتیب حالت‌ها مهم است: اول <Formula inline latex={"m = 0"} /> چک می‌شود، بعد <Formula inline latex={"n = 0"} />، وگرنه حالت سوم. حالت سوم تودرتوست: اول درونیِ <Formula inline latex={"A(m,n-1)"} /> حساب می‌شود، بعد نتیجه‌اش می‌شود ورودیِ بیرونی. هر دو ورودی باید نامنفی باشند.

## چرا این‌قدر سریع؟

چون نتیجهٔ یک فراخوانی، ورودیِ فراخوانی بعدی می‌شود. در فاکتوریل، n فقط در جواب ضرب می‌شد؛ اینجا جوابِ درونی تعیین می‌کند بیرونی چند لایه عمیق شود. چند نقطه برای حس‌گرفتن (با اجرای ماشینی): <Formula inline latex={"A(1,2) = 4"} />، <Formula inline latex={"A(2,2) = 7"} />، <Formula inline latex={"A(2,3) = 9"} /> و <Formula inline latex={"A(3,0) = 5"} />. از این به بعد ورودی‌های کمی بزرگ‌تر جواب‌های باورنکردنی می‌دهند؛ برای همین در عمل فقط نقطه‌های کوچک ردیابی می‌شوند.

<Confused prerequisites={["recursive-function", "ackermann-definition"]} retry="اول A یک صفر را جدا حساب کن (می‌شود ۲)، بعد بگذار سر جای درونیِ A یک یک">
  اگر تودرتویی گنگ است، داخل را یک جعبهٔ بسته بدان: اول عددِ داخل جعبه را حساب کن، بعد جعبه را با همان عدد باز کن.
</Confused>

## جمع‌بندی

در این درس دیدی که:

1. آکرمن سه حالت دارد و ترتیبشان مهم است.
2. حالت سوم تودرتوست: نتیجهٔ درونی ورودیِ بیرونی می‌شود.
3. <Formula inline latex={"A(1,1) = 3"} /> با چهار فراخوانی؛ و همین الگو خیلی زود منفجر می‌شود.

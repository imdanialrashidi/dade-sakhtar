<Prerequisite ids={["recursion-tree-growth"]} />

## دو ابزار شمارش

بازکردن یعنی رابطه را تکراری جایگذاری کنی تا الگو معلوم شود. درخت بازگشت یعنی هر فراخوانی را یک گره بدانی و هزینهٔ هر سطح را جدا جمع بزنی. در درس قبل با همین دو ابزار به <Formula inline latex={"2^{n}-1"} /> رسیدی.

حالا تابع مربع‌ساز را ببین: حالت پایه‌اش ۲ است و هر سطح دقیقاً یک ضرب دارد.

```
int f(int n) {
  if (n == 0) return 2;
  int x = f(n - 1);
  return x * x;
}
```

این تابع فقط یک بار خودش را صدا می‌زند، پس فراخوانی‌ها زنجیرهٔ خطی‌اند نه درخت: از <Formula inline latex={"f(8)"} /> تا <Formula inline latex={"f(0)"} />، یعنی ۹ فراخوانی و ۸ سطحِ دارای ضرب. مقدارها سریع بزرگ می‌شوند (۲، ۴، ۱۶، ۲۵۶ و …)، ولی شمارش ضرب‌ها فقط سطح‌ها را می‌شمرد.

<Formula
  id="mult-count"
  latex={"M(0) = 0,\\quad M(n) = M(n-1) + 1\\ \\ (n \\geq 1)"}
  caption="رابطهٔ شمارش ضرب‌ها"
/>

بازکردنش می‌دهد <Formula inline latex={"M(n) = n"} />. پس برای <Formula inline latex={"n = 8"} /> دقیقاً ۸ ضرب. شمارندهٔ اجرا برای nهای ۱ تا ۹ همین را تأیید می‌کند.

<Callout type="warning" title="دام دو فراخوانی">
  اگر به‌جای متغیرِ واسط بنویسی `return f(n-1) * f(n-1)`، در هر سطح دو فراخوانی ساخته می‌شود و زنجیره تبدیل به همان درخت نمایی درس قبل می‌شود. یک ضرب با دو فراخوانی فرق دارد: اولی هزینهٔ خطی می‌دهد، دومی نمایی.
</Callout>

<Confused prerequisites={["recursion-tree-growth"]} retry="زنجیرهٔ این درس را با درخت درس قبل کنار هم بکش: یکی ۹ گره دارد، یکی ۶۳ گره">
  اگر «پس چرا ۸؟» هنوز سؤال است، سطح‌ها را شماره بزن: ۸ سطحِ دارای ضرب، هر کدام یکی. مقدارِ بزرگِ جواب ربطی به شمارش ندارد.
</Confused>

## جمع‌بندی

در این درس دیدی که:

1. شمارش عمل‌ها با بازکردن و درخت بازگشت انجام می‌شود، نه با حدس.
2. یک فراخوانی در هر سطح یعنی زنجیرهٔ خطی؛ دو فراخوانی یعنی درخت.
3. تابع مربع‌ساز برای <Formula inline latex={"n = 8"} /> دقیقاً ۸ ضرب می‌کند.

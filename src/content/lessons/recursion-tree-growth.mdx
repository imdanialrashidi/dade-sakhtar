در درس قبل هر فراخوانی فقط یک فراخوانی می‌ساخت و زنجیره خطی بود. حالا تابعی را ببین که در هر سطح دو بار خودش را صدا می‌زند؛ همان ایدهٔ «کوچک شو» ولی با دو فرزند به‌جای یکی.

<Prerequisite ids={["recursion-and-factorial"]} />

## تابع دوبرابرشونده

<Formula
  id="doubling-def"
  latex={"R(1) = 1,\\quad R(n) = R(n-1) + R(n-1)\\ \\ (n > 1)"}
  caption="تعریف تابع دوبرابرشونده"
/>

```
int R(int n) {
  if (n == 1) return 1;
  return R(n - 1) + R(n - 1);
}
```

هر گرهٔ درونی دو فرزند روی <Formula inline latex={"n-1"} /> می‌سازد و جوابشان را جمع می‌کند. پس مقدار در هر سطح دو برابر می‌شود: <Formula inline latex={"R(n) = 2\\,R(n-1)"} />.

## کشیدن درخت

با بازکردنِ تکراری همین رابطه، درخت کامل ساخته می‌شود. برای <Formula inline latex={"n = 3"} />:

```
        R(3)
       /    \
    R(2)    R(2)
    / \      / \
 R(1) R(1) R(1) R(1)
```

ردیف‌ها ۱ و ۲ و ۴ گره دارند. مقدار هر برگ ۱ است، پس <Formula inline latex={"R(3) = 4"} />. ولی کل فراخوانی‌ها ۷ است: ۱ به‌علاوهٔ ۲ به‌علاوهٔ ۴.

## چرا نمایی؟

هر یک واحد اضافه‌شدنِ <Formula inline latex={"n"} />، کل درخت را دو برابر می‌کند. روی نردبان رشد فصل قبل، این همان پلهٔ <Formula inline latex={"2^n"} /> است: برای ورودی کوچک بی‌آزار، برای ورودی بزرگ غیرعملی.

<Misconception
  wrong="چون مقدار R شش فقط ۳۲ است، پس هزینه‌اش هم کم است."
  correct="مقدار ۳۲ است ولی ۶۳ فراخوانی لازم داشته است. هزینه تعداد گره‌های درخت است، نه عددی که برمی‌گردد."
/>

<Confused prerequisites={["recursive-function", "doubling-recurrence"]} retry="درخت را برای n مساوی ۳ روی کاغذ بکش و گره‌ها را یکی‌یکی بشمر">
  اگر ۳۲ و ۶۳ قاطی شد، برگ‌ها را با یک رنگ و گره‌های درونی را با رنگ دیگر بشمر: جمع برگ‌ها مقدار است، جمع همه هزینه است.
</Confused>

## جمع‌بندی

در این درس دیدی که:

1. دو فراخوانی در هر سطح، درخت کامل می‌سازد نه زنجیرهٔ خطی.
2. مقدار <Formula inline latex={"R(n) = 2^{n-1}"} /> است و کل فراخوانی‌ها <Formula inline latex={"2^{n}-1"} />.
3. برای <Formula inline latex={"n = 6"} /> مقدار ۳۲ و هزینه ۶۳ است؛ رشد نمایی است.
